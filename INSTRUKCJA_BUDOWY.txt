JAK ZBUDOWAC PROGRAM OD ZERA (3.21.0)
=====================================

1. Rozpakuj CALA paczke do jednego, pustego folderu (np. C:\PMT\build).
   Musza w nim lezec co najmniej: PMT_Delegacje.py, intro_zywa_mapa.py,
   karta_testera.py, wyglad_3d.py,
   zbuduj.py, wersja_exe.txt, pmt_logo.ico.
   Warto dolozyc tla: ciemny.png i jasny.png (bez nich program dziala,
   tylko rysuje tlo zastepcze).

2. Sprawdz wersje:  dwuklik SPRAWDZ_WERSJE.bat
   W zrodle i w wersja.txt ma byc ten sam numer.

3. Przetestuj:  python testy_pmt.py
   Ma wyjsc 91/91. Jesli cokolwiek nie przechodzi - NIE buduj.

4. Zbuduj:  dwuklik ZBUDUJ_EXE_FOLDER.bat   (wariant zalecany)
   Skrypt sam sprawdzi pliki, doinstaluje brakujace biblioteki,
   wyczysci build/, dist/ i pliki .spec, po czym zbuduje program.
   Wynik: dist\PMT_Planer\PMT_Planer.exe

   ZBUDUJ_EXE.bat (jeden plik) jest do wlasnych testow. Ten wariant
   rozpakowuje ok. 48 MB do folderu tymczasowego przy kazdym starcie
   i to on najczesciej obrywa od zabezpieczen Windows. Skrypt zapyta
   o potwierdzenie.

5. Rozdaj CALY folder dist\PMT_Planer (spakowany do ZIP).
   zbuduj.py doklada do tego folderu URUCHOM_PMT.bat, znacznik wersji
   pmt_wersja.txt i 0_NAJPIERW_ROZPAKUJ_CALY_FOLDER.txt (podpowiedz dla
   osob, ktore klikna program w srodku ZIP-a - blad "Failed to load
   Python DLL"). Pakujac recznie: w korzeniu ZIP-a ma byc DOKLADNIE
   JEDEN folder PMT_Planer - luzny plik obok psuje aktualizator 3.21.0/1.

BUDOWANIE NA GITHUBIE (to samo, automatycznie)
  Opublikowanie wydania z tagiem "v3.21.0" uruchamia .github/workflows/
  build.yml. Buduje na Windows, macOS i Linux i dolacza paczki do wydania.
  Gdy paczka Windows jest juz w wydaniu, ten sam automat SAM podbija
  wersja.txt (numer ze zrodla + pierwsza linia opisu wydania; wiersze
  min= i blokada= zostaja). Dziala tez wtedy, gdy wydanie tworzysz przez
  edycje starego wpisu w Releases. Recznie wersja.txt NIE podbijaj -
  numer bez gotowej paczki kaze starym wersjom pobierac ja w kolko.
  Wersja z CI jest budowana z tymi samymi ustawieniami co lokalna:
  --onedir, --noupx, --version-file wersja_exe.txt, ikona, znacznik wersji.

CO NIE POWINNO SIE ZMIENIC
  * --onedir, nie --onefile   (mniej blokad, brak bledu "Failed to load
    Python DLL", szybszy start),
  * --noupx                   (kompresja UPX to najczestsza przyczyna
    falszywych alarmow antywirusa),
  * --version-file            (bez metadanych plik .exe wyglada dla
    SmartScreen jak anonimowy plik z internetu),
  * Python 3.13, nie 3.14     (blad python314.dll u uzytkownikow).

JAK ODCZYTAC WYNIK URUCHOMIENIA
  * rusza animacja startowa            -> wszystko dziala;
  * okno "PMT Planer 3.21.0 - blad startu" -> program wystartowal, ale cos
    zawiodlo pozniej: przeslij plik .pmt_start_blad.txt z katalogu
    uzytkownika;
  * goly traceback w czarnej konsoli   -> uruchomil sie STARY plik,
    a nie ten swiezo zbudowany. Uruchom dokladnie
    dist\PMT_Planer\PMT_Planer.exe.

GDY BUDOWA KRZYCZY "Odmowa dostepu" (WinError 5)
  Poprzedni PMT_Planer.exe najpewniej wciaz dziala i trzyma swoje pliki.
  Zamknij program i okna Eksploratora otwarte w dist\PMT_Planer, po czym
  zbuduj ponownie. Pulpit synchronizowany przez OneDrive potrafi blokowac
  swieze pliki - wtedy najpewniej zadziala budowa w C:\PMT\build.

PODPIS CYFROWY
  Po zbudowaniu: dwuklik PODPISZ_EXE.bat (wymaga wlasnego certyfikatu
  i narzedzia signtool z Windows SDK). To jedyne trwale rozwiazanie
  problemu z blokowaniem programu przez Windows - patrz
  BEZ_BLOKADY_WINDOWS.txt.
