JAK DZIAŁA WYDANIE (żeby wiedzieć, czego się spodziewać)
  1. Kod jest na gałęzi main.
  2. Publikujesz wydanie z tagiem vX.Y.Z (WYDANIE.txt, KROK 6).
  3. GitHub buduje paczki Windows, macOS i Linux i dołącza je do wydania.
  4. Dopiero gdy paczka Windows jest w wydaniu, GitHub sam wpisuje numer
     do wersja.txt na main — od tej chwili programy u ludzi widzą
     aktualizację i pobierają ją jednym kliknięciem.
  Budowanie testowe (WYDANIE.txt, KROK 5) robi punkt 3 bez wydania
  i bez punktu 4 — paczkę widzisz tylko Ty.

OBOWIĄZKOWA AKTUALIZACJA (wersja.txt, dwie ostatnie linie)
  min=X.Y.Z       wersje starsze niż ta dostają okienko z odliczaniem
  blokada=RRRR-MM-DD   po tej dacie starsza wersja się nie uruchomi
  ZAWSZE ZMIENIAJ OBIE LINIE NARAZ, datę 14 dni naprzód. Program i tak
  nikogo nie odetnie wcześniej niż 14 dni od chwili, gdy zobaczył nowy
  próg — ale z poprawną datą wszyscy widzą to samo odliczanie.

TESTY
  python testy_pmt.py   pełny zestaw (ok. 1100 sprawdzeń, kilka minut)
  Na GitHubie biegną same przy każdej zmianie (zakładka Actions,
  przebieg „Testy"). Liczy się GÓRNY wiersz listy — starsze przebiegi
  zostają na liście na zawsze. Gdy coś padnie, nazwa sprawdzenia jest
  wypisana przy czerwonym znaczku.
